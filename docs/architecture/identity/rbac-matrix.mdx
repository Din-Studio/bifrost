本页定义 OSS 版三个系统角色（Admin / Developer / Viewer）对每条管理路由的权限。行来自 `transports/bifrost-http/server/server.go:2312-2529` 实际调用的 `RegisterRoutes` / `RegisterRoutesWithOverrides`，以及各 handler 内注册的 `(方法, 路径)`；资源名只取 `ui/app/_fallbacks/enterprise/lib/contexts/rbacContext.tsx:4-43` 已有的 `RbacResource` 值，操作名只取同文件 `:46-55` 的 `RbacOperation` 值。**不新造资源名、不新造操作名。**

本矩阵是 Phase 3 seed 数据的唯一来源：种子测试逐行比对本页表格，任何差异即失败（AC-RBAC-5）；矩阵每一行都对应一条"非授权角色调用 → 403"的集成测试（AC-RBAC-1）。

## 操作语义

| 操作 | 语义 | v1 使用 |
|---|---|---|
| `View` | 列表与详情读取；对含密钥的实体返回**脱敏**值 | 使用 |
| `Read` | enum 中与 `View` 并存的历史值；OSS 只用 `View`，`Read` 作别名映射到 `View` | 别名 |
| `Create` | POST 新建 | 使用 |
| `Update` | PUT / PATCH 修改，含 rotate、reconnect、reauthorize、override 等状态变更 | 使用 |
| `Delete` | DELETE 删除，含清空日志、清缓存 | 使用 |
| `Reveal` | 读取密钥明文（provider key value、VK value） | 使用，仅 Admin |
| `Download` | 日志导出 | 使用，Admin 与 Developer 对 `Logs` |
| `CreateStandalone` | 企业版语义 | v1 不用 |

## 系统角色

| 角色 | 定义 |
|---|---|
| **Admin** | 全部资源全部操作。break-glass 账密登录（`admin` 会话）恒为 Admin。 |
| **Developer** | 对 `ModelProvider`、`VirtualKeys`、`MCPGateway`、`VirtualMCPs`、`Plugins`、`RoutingRules`、`PromptRepository`、`SkillsRepository`、`Teams`、`Customers`、`Governance` 为 `View` / `Create` / `Update` / `Delete`；对 `Logs`、`MCPLogs`、`Settings`、`Users`、`Metrics`、`Notifications`、`FeatureFlags`、`RBAC` 为 `View`；对 `Logs` 另有 `Download`；无 `Reveal`。 |
| **Viewer** | 全部有路由资源 `View`；无 `Reveal` / `Create` / `Update` / `Delete` / `Download`。 |

说明：

- `Reveal` 仅 Admin（AC-RBAC-4、AC-AUTH-13）。`ModelProvider.View` 与 `VirtualKeys.View` 对非 Admin 返回脱敏值；`handlers/governance.go:1599-1633,1888-1912` 与 `tables/virtualkey.go:320-331` 今日直接返回明文，Phase 3 必须按此矩阵改为脱敏。
- Viewer 的任何 `Create` / `Update` / `Delete` / `Reveal` / `Download` 都必须服务端 403（AC-RBAC-3）。
- `RBAC` 资源 v1 只读：系统角色由代码 seed，无角色编辑 API（PRD 已明示为首期裁剪）。
- `Notifications.Create`（`POST /api/notifications`）留给 Admin，用于系统广播；Developer / Viewer 只订阅。
- `Users.Create` 指管理员手动建号；SSO JIT 建号与 SCIM / bridge 写入走服务层，不经此权限。
